# 在线审计查漏补缺双流水线设计

## 目标

将在线审计从只报告差异的检查器改造成持续查漏补缺流程：在线重新扫描全部已办事项，缺失附件立即补下载；缺少成功 Markdown 产物的本地附件进入独立转换队列。扫描与 Markdown 转换由两个独立系统进程共同推进，并可分别暂停和继续。

## 安全与数据边界

- OA 集成保持只读，只允许读取事项和下载附件，不审批、回复、删除、转发或修改 OA 记录。
- Markdown Worker 不访问 OA，只读取本地已验证归档文件并写入配置的 Markdown 输出目录。
- 不删除本地多余附件，不覆盖已验证归档；下载复用现有内容寻址与校验逻辑。
- OA 标识继续以文本保存，归档路径继续相对 `data_root` 保存。
- 实施日志不得包含正文、Cookie、凭据、真实附件内容或其他机密数据。

## 架构

系统包含两条相互独立的持久化流水线。

### 在线扫描与补下载流水线

现有在线审计运行和审计 Worker 负责：

1. 逐项在线读取已办事项的附件清单。
2. 只统计真实附件角色，不把 OA 正文计入附件数。
3. 与本地已验证附件对比。
4. OA 附件多于本地已验证附件时，调用现有安全归档流程补下载缺失内容。
5. 下载事务提交后，将仍缺少成功 Markdown 产物的已验证附件幂等加入 Markdown 队列。
6. 对本来已完整下载、但缺少 Markdown 的附件同样加入 Markdown 队列。

扫描的暂停和继续只影响继续访问 OA 与补下载，不改变 Markdown 队列状态。

### Markdown 转换流水线

新增独立的 Markdown Worker 系统进程。它只消费 Markdown 转换任务：

1. 原子领取一条待处理任务并持有可恢复租约。
2. 检查源附件仍然存在、已验证且尚无当前 schema 版本的成功 Markdown 产物。
3. 调用现有 Markdown 导出服务进行转换。
4. 记录成功、失败、耗时和脱敏错误码，然后继续下一条任务。

Markdown 暂停只停止领取新任务。当前正在转换的单个任务允许安全结束，在线扫描继续运行。进程异常退出后，过期租约可被恢复，不会永久卡住任务。

## 队列与幂等

新增专用 Markdown 转换任务表，不与 OA 操作任务竞争同一个 Worker：

- 每个 `source_file_id + schema_version` 最多存在一个有效任务。
- 状态包括 `queued`、`running`、`succeeded`、`failed`、`paused` 不用于单任务；全局暂停状态单独保存。
- 已存在成功 `MarkdownExport` 时不入队。
- 已排队或正在运行时不重复入队。
- 源文件内容或 Markdown schema 版本变化时允许产生新的转换任务。
- 失败任务保留错误码和尝试次数，可由页面重新排队；失败不阻塞其他任务。

两个 Worker 使用各自的任务表/查询范围、进程所有者和运行状态文件，避免互相领取任务或覆盖进度。

## 进度口径

审计页面同时展示两组独立状态。

扫描与补下载：

- 总事项、已复查、剩余事项。
- 附件一致、发现缺失、成功补下载、补下载失败。
- 本地附件较多、OA 访问失败、当前事项和单项耗时。

Markdown 转换：

- 已发现需转换附件、排队中、转换中、转换成功、转换失败。
- 当前附件的脱敏显示名和耗时。
- 队列状态以及 Markdown Worker 是否在线。

“待 MD 化”只根据已验证附件与当前 schema 版本的成功 `MarkdownExport` 差集计算，不影响附件一致性判断。

## WebUI 行为

- 扫描区域提供“开始在线查漏补缺”“暂停扫描”“继续扫描”。
- Markdown 区域提供“暂停 MD 化”“继续 MD 化”和失败任务重试入口。
- 两个区域分别显示进度条、状态和实施日志。
- 后端轮询静默更新数据，不重置选中的分页、不改变滚动位置、不造成页面跳动。
- “事项复查结果”继续分页并固定放在页面最下方。
- 页面明确区分附件缺失、本地较多、待 MD 化、转换失败，避免用一个“数量不符”混合表达。

## 错误处理

- 单个 OA 事项访问或下载失败：记录在该事项和扫描日志中，扫描继续。
- 单个 Markdown 转换失败：记录在 Markdown 任务和 Markdown 日志中，转换队列继续。
- 数据库忙或进程退出：依靠短事务、租约和幂等键恢复。
- 源文件丢失或校验状态失效：Markdown 任务失败并记录稳定错误码，不尝试访问 OA；后续在线扫描可再次发现并修复附件。

## 测试与验收

- 单元测试覆盖附件计数口径、Markdown 缺口识别、幂等入队、分别暂停/继续、失败后继续和租约恢复。
- Worker 测试证明 Markdown Worker 不领取 OA 任务，审计 Worker 不领取 Markdown 任务。
- 集成测试证明审计发现缺失附件后完成归档并入 Markdown 队列，同时审计无需等待转换完成即可继续下一事项。
- API 测试覆盖两套进度、控制按钮、日志、分页和失败重试。
- 前端类型检查和生产构建通过。
- 本地 systemd 启动两个 Worker，人工验证两条进度可同时增长，任意暂停一条不会停止另一条。

## 不在本次范围

- 不修改 Markdown 内容格式或引入新的文档解析引擎。
- 不并发启动多个 OA 浏览器扫描进程。
- 不自动删除本地多余文件。
- 不对 OA 执行任何写操作。
