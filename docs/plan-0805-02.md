**项目仓库：** `KenGGG/OARadar`

---

## 一、总体目标

将 OARadar 完善为一套长期稳定运行的只读 OA 工作台：

```text
工作日上午 09:05 至 17:05，每小时执行一次
                │
       ┌────────┴────────┐
       │                 │
   扫描全部待办       增量扫描已办
       │                 │
新增或实质变化       新增或遗漏事项
       │                 │
抓取详情和附件       下载并校验附件
       │                 │
本地解析和摘要       原始文件归档
       │                 │
飞书发送简化卡片     加入 Markdown 队列
                         │
                    llm_wiki / Obsidian
```

最终必须满足：

1. OA 访问始终只读，不进行审批、回复、删除、转发或修改。
2. 首次上线不推送全部存量待办。
3. 待办未发生变化时不重复抓取、不重复摘要、不重复通知。
4. 待办发生实质变化时生成新摘要，并只推送一次新版本。
5. 已办事项成功归档后自动进入 Markdown 转换队列。
6. 定时任务中断、服务器重启或 worker 崩溃后能够恢复。
7. 所有归档路径、数据库路径和 Markdown 路径保持一致。
8. 飞书 webhook、签名密钥、OA Cookie、模型密钥不进入代码、YAML、日志或 Git。
9. 每次扫描、通知、下载、解析和失败重试均有持久化状态可查询。
10. 停机超过数小时或数天后，系统仍可补齐遗漏已办。

---

# 二、明确不做的事项

本轮不得实施以下内容：

* 不修改 OA 中的任何事项。
* 不向飞书发送完整正文、附件内容、审批意见全文或原始证据。
* 不把 OA 凭据、Cookie、飞书 webhook 或密钥写入配置文件。
* 不在每小时任务中全量下载所有历史已办。
* 不让 systemd 脚本直接承担复杂业务状态管理。
* 不绕过现有 SQLite 队列、资源租约和幂等机制。
* 不删除本地历史文件或历史数据库记录。
* 不直接在真实 `data/` 上运行单元测试。
* 不在没有 dry-run、备份和回滚方案的情况下迁移归档目录。

### 2.2 待办扫描必须取得完整快照

不要依赖固定 `limit=500` 判断整个待办状态。

增加正式方法：

```python
PendingAdapter.discover_all_pages(...)
```

要求：

* 扫描至 OA 返回的最后一页；
* 按 `affair_id` 去重；
* 确认 `pages_scanned == source_total_pages`；
* 完整快照时才允许关闭本地已消失事项；
* 快照不完整时不得把未看到的事项设为 inactive；
* 超过安全页数时标记 partial 并告警。

CLI 旧的 `pending discover --limit` 可继续用于人工检查，但正式定时任务必须调用完整扫描接口。

### 2.3 已办增量扫描改为“已知边界”算法

不得固定只扫描三页。

建议算法：

```text
从第1页开始扫描
    ↓
每页与 oa_manifest_items 比较
    ↓
持续记录新增事项
    ↓
遇到连续 N 条已知且内容未变化的事项
    ↓
认为到达稳定边界并停止
```

参数建议：

```text
known_boundary_count = 20
max_pages = 20
```

停止条件：

```text
1. 到达 OA 最后一页；
2. 连续遇到 20 条本地已知且未变化事项；
3. 达到 max_pages 安全上限。
```

达到安全上限但没有找到已知边界时：

```text
- 本次状态记为 partial；
- 不假装同步完整；
- 安排 nightly 全量清单同步；
- 记录 review_queue 或系统告警。
```

### 2.4 避免丢失新增已办下载任务

当已有 `full_manifest_retry` 正在运行时，新发现的 `target_keys` 不应仅等待下一小时。

实现以下任一方案：

方案A，推荐：

```text
每个新增已办建立独立、幂等的 realtime_done PipelineTask
```

方案B：

```text
安全地把新 key 合并进现有 OperationJob.parameters_json
```

推荐方案A，因为：

* 粒度更小；
* 幂等更清晰；
* 不需要并发修改大型 job 参数；
* 实时事项可使用高于历史回填的优先级。

幂等键：

```text
realtime-done:<oa_item_key>:archive-v1
```

### 2.5 夜间任务必须真正补齐遗漏

当前夜间任务不能只做清单数量同步。

`oa schedule nightly` 应完成：

```text
1. 全量扫描已办列表；
2. 同步 OAManifestItem；
3. 应用排除规则；
4. 为所有 pending_download / download_failed 项建立下载任务；
5. 为已下载但未 Markdown 化的附件建立 MarkdownTask；
6. 对 sending、running 且租约过期的任务做恢复；
7. 输出完整统计。
```

夜间任务只负责“发现并入队”，重型下载和解析仍交给常驻 worker。

- 可自动重试

# 七、回滚方案

一旦发生以下情况立即停止 timer：

```text
大量重复飞书消息
路径迁移失败
数据库与文件路径不一致
已办附件无法打开
worker持续失败
Markdown任务异常暴增
OA账号被频繁重新登录
```

停止：

```bash
systemctl --user stop \
  oaradar-hourly.timer \
  oaradar-nightly.timer \
  oaradar-worker.service \
  oaradar-markdown-worker.service
```

回滚原则：

1. 未执行路径迁移时，可直接回滚代码。
2. 已执行路径迁移后，不得只回滚代码。
3. 路径迁移后回滚必须同时恢复：

   * 数据库备份；
   * `data/raw` 和 `data/archive` 备份；
   * Markdown来源目录备份。
4. 恢复完成后先运行 `oa doctor`，再启动 worker。
5. 未确认原因前不得重新启用 timer。
