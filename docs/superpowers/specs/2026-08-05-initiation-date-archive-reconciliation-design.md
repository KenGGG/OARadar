# 按发起时间重排 OA 归档设计

## 目标

将所有已办事项的原始文件和 Markdown 成果按 OA 列表中的“发起时间”归档到
`YYYY/MM`，修复当前按办结时间或采集时间归档造成的年月错位。迁移同时更新数据库、
Manifest、Markdown 元数据和资源目录，并让后续采集永久使用同一规则。

## 日期口径

- 已办事项的唯一首选归档日期是 OA 列表中的发起时间。
- 先使用数据库中已可信保存的发起时间，再通过只读在线扫描补齐缺失值。
- 在线扫描后仍无发起时间的事项进入 `raw/done/unknown/`，不得使用办结时间、接收时间、
  首次发现时间或当前时间伪装成发起时间。
- 发起时间以 OA 页面显示的本地日期为准，按 `Asia/Shanghai` 计算 `YYYY/MM`，不得因 UTC
  转换跨日或跨月。

## 数据模型

`OAItem` 增加可空的 `initiated_at` 字段，作为归档路径的规范日期来源。已办列表发现、
完整清单同步、批次同步和在线审计均应写入该字段；相同事项再次扫描时允许用 OA 的明确值
补齐或纠正旧值。

迁移计划以事项为单位，至少记录事项 ID、旧目录、新目录、日期来源、文件数量、Markdown
数量、状态和错误码。OA 标识继续按文本保存；日志和 WebUI 不输出附件正文、Cookie 或凭证。

## 在线校准流程

1. 暂停在线审计和 Markdown 队列的新任务领取；等待当前单项安全结束。
2. 只读遍历全部已办列表，读取事项标识、标题、发起时间和办结时间。
3. 以稳定 OA 标识匹配本地事项，写入 `OAItem.initiated_at`，并保留本次观察证据时间。
4. 对未匹配、重复匹配、日期无法解析的事项记录审计错误，不猜测日期。
5. 扫描结束后生成迁移计划，先完成冲突检查，再进入文件移动阶段。

OA 集成保持只读，不审批、回复、删除、转发或修改任何 OA 记录。

## 路径规划

已知发起时间的目标目录为：

`raw/done/<YYYY>/<MM>/<安全标题>_<workitem_id_text>`

未知发起时间的目标目录为：

`raw/done/unknown/<安全标题>_<workitem_id_text>`

Markdown 根目录继续镜像原始目录，因此迁移到对应的 `workspace/markdown/...` 路径；与单个
Markdown 同名的 `.assets` 目录必须一起移动。目录命名继续使用现有安全文件名算法，避免
引入新的名称变化。

## 事务与文件安全

迁移分为“计划、暂存、验证、提交”四步：

1. 计划阶段只读，拒绝目标目录已被另一事项占用、源目录缺失或源路径越界的记录。
2. 暂存阶段在同一数据根内移动到任务专属暂存路径，以保证最终重命名为原子操作。
3. 验证阶段核对源文件数量、大小和已有 SHA-256；Markdown 及资源按存在性和数量核对。
4. 提交阶段在一个数据库事务中更新所有相对路径，再将暂存目录原子发布到目标路径。

若单个事项失败，只回滚该事项，其他事项可继续；不得删除无法确认归属的目标目录。迁移过程
可重复执行，已在正确位置的事项应成为无操作任务。

## 需要同步更新的引用

- `OAItem.archive_relpath` 与 `OAItem.initiated_at`
- `ArchivedFile.local_relpath`
- 已办清单和批次项中的归档、Manifest 相对路径
- `MarkdownExport.source_relpath` 与 `markdown_relpath`
- `metadata.json`、`manifest.json` 中的本地相对路径
- Markdown frontmatter/正文中由系统生成的源文件相对路径
- 知识库投影中保存的源路径；必要时在迁移完成后执行本地重建

Markdown 正文和 MinerU 解析结果不重新转换，只安全移动并改写系统生成的路径字段，避免
重复消耗 GPU，也避免改变已经人工检查过的转换内容。

## 后续采集规则

已办列表发现模型必须携带发起时间。`archive_collaboration_detail` 只使用规范发起时间创建
目录；缺失时写入 `unknown`，不得再回退到办结时间或当前时间。再次在线扫描补齐日期后，
复用同一迁移器把 `unknown` 事项移入正确年月。

## WebUI

审计页面增加“发起时间归档校准”区域，显示：扫描总数、已取得发起时间、缺失时间、待迁移、
迁移中、迁移成功、迁移失败和已正确归档。提供开始、暂停、继续和仅重试失败项控制；实施日志
只显示事项级状态和脱敏错误码。页面轮询不得重置当前分页或滚动位置。

## 验收标准

- 用户报告事项归档在 `2022/04`。
- 所有能从 OA 获取发起时间的事项，其原始目录年月与发起时间一致。
- 对应 Markdown 和资源目录与原始目录保持镜像关系。
- 数据库不存在仍引用旧路径的文件或 Markdown 记录。
- 未知发起时间事项全部位于 `unknown`，并在 WebUI 中单独计数。
- 迁移前后已验证原始文件数量和 SHA-256 不变。
- 暂停、继续和失败重试可独立于 Markdown 转换流程工作。
- 自动化测试覆盖日期选择、时区边界、未知日期、冲突、幂等、单项回滚和路径引用更新。

## 非目标

- 不修改 OA 端任何事项。
- 不根据标题、正文、文件时间戳或目录时间推测发起时间。
- 不重新运行已经成功的 Markdown 内容解析。
- 不清理来源不明或发生冲突的目录；此类情况进入人工复核。
