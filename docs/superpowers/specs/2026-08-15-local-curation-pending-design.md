# 本地 OA 知识编目与待办通知设计

**日期：** 2026-08-15
**状态：** 已批准
**范围：** 仅使用本机 `qwen3.5:9b`，不依赖 CodeBuddy 或远程模型

## 1. 目标成果

OARadar 建立两条生产流水线，共用现有配置、SQLAlchemy 数据库、原始归档、解析产物、本地模型安全边界、Worker 和运维控制能力。

1. 可重建的 Curated 知识层把一个不可变 OA 资料包转换为零个或多个规范知识文档，负责去除流程噪声、保留忠实 Source Markdown、记录全部来源关系并发布到稳定目录。
2. 定时待办流水线只读刷新 OA，为每个新的内容版本在受控上下文内生成摘要，并通过飞书执行一次性通知；发送结果不确定时停止自动重试，等待人工核对。

未跟踪的 `codebuddy/` 原型只作为早期架构参考，不是运行依赖，不得成为第二套事实数据库，也不得把 OA 派生报告带入 Git。

## 2. 信任边界与不变量

- OA 内容只留在本机。唯一允许的文本模型端点是回环地址上的 Ollama，唯一生产文本模型是 `qwen3.5:9b`。
- 原始归档文件和 Source Markdown 是不可变输入；`data_root` 下的 Curated 文件是可删除、可重建的投影。
- 模型可以分类和选择来源，但不得生成或改写规范正文；发布器只能从已校验 Source Markdown 确定性组装正文。
- 模型返回的每个来源键在持久化或发布前都必须验证属于当前 OA 资料包。
- OA 边界上的所有标识符按文本保存；发布路径一律相对 `data_root`。
- `plan`/预检不得写入 Curated 文件或编目数据库记录。
- 容器树最多遍历 10 层。达到上限必须记录 `depth_limit_reached`，不得把该资料包报告为完成。

## 3. 共享的本地模型上下文预算

`LocalModelProfile` 通过 Ollama `/api/show` 查询模型公开的上下文长度，再应用运维配置的安全上限并短时缓存；探测失败时使用保守回退值。

```text
可用输入 token = 上下文窗口 - 最大输出 token - 系统提示 token - 安全余量
```

系统采用偏保守的 token 估算。长来源按标题和段落边界分块并保留少量重叠；分类先执行分块映射，再使用压缩结果归并。最终正文发布仍读取完整来源文件，不使用分块摘要替代正文。任何原始 OA 资料包都不能不受限制地塞进一次模型请求；待办摘要复用同一预算组件。

## 4. Curated 知识编目流程

### 4.1 资料包清点

资料包构造器从已有 `LogicalItem`、快照、`SourceAttachment`、压缩包成员、内容对象和有效解析产物出发，生成顺序稳定的清单。清单只包含稳定标识、相对来源路径、哈希、角色提示、标题和受限摘录。

确定性规则先识别明显流程壳、重复二进制、签章页、空解析结果和低价值流转表单；高置信正式文件特征予以保留。只有规则无法确定的候选才提交模型。

### 4.2 结构化决策

模型必须返回符合版本化 Schema 的严格 JSON，包括：资料包处置和置信度、零个或多个文档、文档类型、发文机构、发文编号、规范标题、发布日期、主题/客户/项目/阶段、有序正文与附件来源、重复提示和证据来源键。

Schema 校验失败、引用未知来源、来源角色冲突或置信度不足时，结果进入 `needs_review`；系统不得猜测元数据。

### 4.3 持久化与失效更新

已有 `KnowledgeDocument`、`SourceReference` 和 `OAItemDocumentRelation` 继续保存规范知识关系。编目运行/决策层只记录资料包状态和决策元数据，不复制原始归档事实。

输入签名由有序来源哈希、规则、提示词、Schema、模型、上下文预算和相关配置版本共同计算。成功签名未变化时自动跳过；输入变化时创建新决策版本并原子重新发布。

高置信正式文件优先使用“发文机构 + 发文编号”形成规范身份，其他文档使用内容集合哈希。多个 OA 事项可以共同指向一个知识文档。精确哈希用于全局去重；无法确定的近似重复进入人工复核。发布只替换受管理目录，并在新版本成功交换后清理旧路径。

### 4.4 稳定输出目录

- 正式文件：`workspace/curated/oa/正式文件/{发文机构}/{年份}/{文号}_{标题}/`
- 公司内部：`workspace/curated/oa/公司内部/{主题}/{YYYY-MM}/{标题}/`
- 项目资料：`workspace/curated/oa/项目资料/{客户}/{项目}/{阶段}/{标题}/`
- 待复核：不发布规范目录，只记录本地状态和原因。

每个发布目录包含 `正文.md`、`附件01_名称.md` 等有序附件、`_manifest.json` 和 `_index.md`。头部元数据记录规范 ID、决策版本、来源哈希、来源关系和相对溯源路径。路径组件经过安全净化、长度限制和稳定冲突后缀；发布使用暂存目录和原子重命名。

## 5. Curated 运维入口

`oa curate` 提供：

- `plan`：只统计资料包和规则/模型分流，不写数据；
- `run`：运行有上限的小批次；
- `retry`：重试失败项或人工选择的复核项；
- `validate`：验证签名、来源归属、哈希、路径、清单和索引；
- `report`：默认只输出汇总数量和原因码，不打印 OA 内容。

运行状态和报告位于 Git 忽略的 `data_root/runtime/curation`。任何全量回填都不得隐式启动。

## 6. 待办刷新与通知

`scheduled_sync → pending_sync → detail_sync → pending_parse → pending_summary → notify_feishu` 是唯一待办路径。

- Discovery 哈希和不可变快照定义待办内容版本。
- 本地预算限制详情和附件证据；长附件先分块归纳，再与详情快照归并。
- `SummaryVersion.input_hash` 和飞书幂等键使未变化扫描成为无操作，内容变化产生新通知版本。
- 单条失败相互隔离并可重试；模型 Schema 失败时生成明确标记的确定性证据降级结果，不得编造内容。
- 飞书 `unknown_outcome` 不自动重试，必须人工核对。
- 只有明确返回 `sent` 后才清理业务内容，并保留最小去重账本。
- 浏览器只读访问 OA，不增加审批、回复、删除或转发动作。

systemd 定时器、健康检查、状态命令和运维手册必须验证模型可达性、调度新鲜度、队列失败、飞书配置和未知发送结果，同时不得暴露 OA 内容。

## 7. 评估与上线顺序

所有自动化夹具只能使用合成或不可逆脱敏数据。金标覆盖 0～N 文档边界、元数据、来源角色、去重、未知来源、路径冲突、上下文分块、签名失效、原子失败、断点续跑、待办版本、飞书结果和原始归档不可变性。

上线顺序为：规则只读预检 → 合成/金标评估 → 运维人员选择的本地小样本 → 有边界的小批次。
在没有后续明确授权时，系统不得自动启动全量历史回填。2026-08-16 用户已批准对全部存量已办
持续重建，因此当前生产任务可以在“完整线上核验完成 → 安全 legacy 路径迁移完成”两道门禁通过后
自动续跑；差异项、缺件项和深度异常项仍不得进入全量发布。任何阶段都不得自动发送真实飞书
测试消息。
