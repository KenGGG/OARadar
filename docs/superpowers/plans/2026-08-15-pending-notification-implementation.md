# 待办摘要通知实施计划

> **Codex 执行要求：** 在用户授权的当前 OARadar 工作区中使用测试驱动开发；不提交、不推送；绝不发送真实飞书测试消息。

**目标：** 完成定时只读待办刷新、本地上下文受控摘要和可靠飞书通知流水线。

**架构：** 加固现有持久化流水线，不建立第二套调度器。复用不可变快照、摘要版本、流水线任务、通知投递账本、清理策略、systemd 模板和共享本地模型预算。

**技术栈：** Python 3.12、Typer、Pydantic、SQLAlchemy、systemd 模板、pytest

**设计说明：** `docs/superpowers/specs/2026-08-15-local-curation-pending-design.md`

### 任务 1：刻画现有状态机

1. 为未变化、内容变化、单项失败隔离、首次基线不通知、可重试失败、未知发送结果、确认发送后清理和 OA 只读增加合成测试。
2. 修改生产代码前运行测试并记录真实缺口。

### 任务 2：受上下文限制的待办证据与降级

1. 编写失败测试，证明每次调用都在预算内、长附件使用 map-reduce、来源顺序稳定、Schema 失败产生明确标记的证据降级结果。
2. 使用共享上下文预算实现分块摘要和最终归并。
3. 提升提示词/签名版本，使旧摘要安全失效。
4. 验证无法选择远程端点。

### 任务 3：补齐 Worker 与投递恢复缺口

1. 每个确认缺口先建立失败回归测试。
2. 实现最小状态转换修复。
3. 验证同版本只发送一次、内容变化产生新投递、失败隔离重试、未知结果不自动重发以及仅 `sent` 清理。

### 任务 4：部署、健康检查与运维

1. 测试本地模型/上下文、定时器、队列新鲜度/失败、飞书就绪状态和未知结果可见性。
2. 实现隐私安全的状态输出和配置检查。
3. 把 systemd 单元渲染到临时目录并验证，不在自动测试中启用或重启服务。
4. 把安装和重载命令记录为运维人员动作。

### 任务 5：端到端合成证明

1. 使用伪造详情采集、伪造本地模型和伪造飞书传输运行合成定时扫描。
2. 断言首个可通知版本发送一次、未变化发送零次、内容变化再发送一次、未知结果不重试、只有 `sent` 才清理。
3. 运行完整测试、CLI/配置检查、敏感输出扫描和部署渲染检查。

### 验证

自动验证不修改真实 OA、不发送飞书消息、不重启服务、不启用定时器。所有本地检查通过后，再执行用户授权的生产部署。
