# Curated 知识编目实施计划

> **Codex 执行要求：** 在用户授权的当前 OARadar 工作区中使用测试驱动开发；不提交、不推送。当前 Goal 高于模板中的提交步骤。

**目标：** 建立仅限本机、上下文受控、支持增量处理的“一个 OA 资料包 → 0～N 个规范知识文档”流水线。

**架构：** 在现有生命周期、内容和知识表之上增加版本化编目决策与确定性原子发布。规则先去噪；本地 `qwen3.5:9b` 只作受限结构化决策；完整 Markdown 从校验通过的解析产物中复制。

**技术栈：** Python 3.12、Typer、Pydantic、SQLAlchemy/Alembic、httpx、pytest

**设计说明：** `docs/superpowers/specs/2026-08-15-local-curation-pending-design.md`

### 任务 1：强制并测量本地模型边界

**文件：** 修改 `config.py`、`enrich/llm_client.py`、`enrich/provider.py`；新建 `enrich/context_budget.py`；测试位于上下文、配置和模型客户端相关测试。

1. 先为远程提供方拒绝、Ollama 上下文探测/回退、保守 token 估算、分块边界和超限拒绝编写失败测试。
2. 实现模型档案、估算器、分块器和请求保护。
3. 移除生产 Agnes 选择，同时保留旧配置的安全迁移读取。
4. 运行专项测试。

### 任务 2：持久化编目运行和决策

**文件：** 修改 `db/models.py`；新建迁移 `0030_curated_knowledge.py` 和 `curation/schemas.py`。

1. 测试运行状态、输入签名、版本化决策、规范元数据、多对多来源和唯一约束。
2. 实现模型和前向迁移，父版本为 `0029_oa_gone`。
3. 验证全新升级和重复初始化安全。

### 任务 3：构建确定性资料包清单和规则

**文件：** 新建 `curation/package.py`、`curation/rules.py` 及对应测试。

1. 使用合成数据测试稳定有序清单、来源哈希、资料包成员、流程噪声抑制、零文档结果和深度上限。
2. 基于现有生命周期和解析事实实现只读清点。
3. 实现版本化高精度规则和不确定项模型分流。
4. 验证原始归档和 Source Markdown 哈希不变。

### 任务 4：生成受控结构化决策

**文件：** 新建 `curation/classifier.py`、`curation/prompts.py` 及对应测试。

1. 测试严格 0～N Schema、map-reduce 分块、非法来源拒绝、低置信复核和确定性降级。
2. 使用共享预算实现规则优先和本地模型调用。
3. 持久化前验证所有来源键属于当前资料包。
4. 只使用伪造本地客户端运行专项测试。

### 任务 5：规范化、去重和原子发布

**文件：** 新建 `curation/canonical.py`、`curation/publisher.py` 及对应测试。

1. 测试正式/内部/项目路径、冲突后缀、全局精确去重、多 OA 来源、来源顺序、清单/索引、原子失败和陈旧路径清理。
2. 使用现有知识表实现规范键优先级和多来源关系。
3. 从完整有效 Source Markdown 确定性渲染并原子交换目录。
4. 确认模型文字不会进入规范正文。

### 任务 6：增量服务和安全 CLI

**文件：** 新建 `curation/service.py`、`curation/report.py`；修改 `cli.py` 及对应测试。

1. 测试签名、未变化跳过、变化失效、恢复/重试、预检不写入、批次上限、校验和隐私安全报告。
2. 以保守小批次实现 `curate plan/run/retry/validate/report`。
3. 运行报告只写入被忽略的 `data_root/runtime/curation`。
4. 运行编目测试套件和 CLI 注册检查。

### 任务 7：金标评估与文档

1. 在 `tests/fixtures/curation/` 增加正式文件、公司内部、项目资料、纯噪声、多文档、重复和低置信合成金标。
2. 使用确定性伪模型输出运行评估。
3. 记录预检、小批次上线、复核、校验和重建方法。

### 验证

运行编目专项测试、迁移测试、CLI 帮助、完整 `pytest`、敏感文件/状态审计和位于被忽略
`data_root` 的预检。原计划要求先由运维人员选择样本；该门槛已完成，且用户在 2026-08-16
进一步批准真实历史全量回填。全量任务必须保持持久化、可暂停和断点续跑，并且只能在完整
线上核验与安全路径迁移完成后领取 canonical 原件；不能为追求进度绕过差异复核。
