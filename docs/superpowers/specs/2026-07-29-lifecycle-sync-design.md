# OA 待办与已办生命周期同步设计

## 目标

WebUI 只把 OA 当前仍存在的事项显示为“待处理”，完整更新已办清单，并以全库口径展示 OA 已办总数、成功下载事项数和已验证附件数。待办采集完成后生成 Markdown 与 Ollama 摘要；同一事项在 OA 中转为已办后，可靠关联原待办并按已办规则归档最终版本。

所有 OA 操作保持只读。OA 内容、附件、身份标识、配置和运行数据继续只存放在本地 `data_root`，测试只使用合成数据。

## 同步与状态语义

- 一次成功的待办列表刷新视为完整当前态快照。刷新开始时记录批次，列表中出现的事项更新 `last_seen_at`；本批次未出现且此前为活动状态的待办改为非活动状态，但不删除其采集记录、摘要或本地文件。
- 只有 `channel=pending` 且 `occurrence_status=active` 的记录进入待处理页面和实时待办队列。因此 OA 当前为 5 项时，页面必须显示 5 项，而不是历史累计数。
- 日常已办同步扫描最新三页，以较低延迟发现新增已办；WebUI 提供“全量核对”按钮，复用现有可恢复的全量清单任务扫描全部页面。任务展示进度、完成或失败状态，重复触发不创建并行全量任务。
- 已办清单是 OA 已办总数的权威本地镜像。下载、解析和摘要状态是独立的处理状态，不得用已下载数量冒充已办总数。

## 生命周期处理

待办流水线顺序为：详情与身份采集、正文/流程/附件下载及校验、内容转 Markdown、Ollama 待办摘要。未启用通知时摘要成功即完成任务，不进入不存在的通知阶段；摘要结构校验失败保留明确错误并按既有重试策略处理。

日常或全量已办发现记录后，使用 `affair_id + summary_id + process_id` 与待办记录严格匹配。匹配成功时：

1. 创建或更新共享同一 `logical_item_id` 的已办 occurrence；
2. 将待办 occurrence 关闭，并把逻辑事项标记为已办确认；
3. 将已办最终版本放入高优先级 `realtime_done` 队列；
4. 按已办规则重新下载并校验最终正文、流程和附件，再解析 Markdown、生成最终知识摘要；
5. 保留待办快照及待办摘要作为历史证据，不覆盖最终已办版本。

身份字段不完整或不一致时不得自动合并，需创建去重的人工复核记录；旧待办可以退出当前列表，但不能因此被错误标为已办。所有 OA 浏览任务共用资源租约，实时待办和实时转已办优先于历史回填。

## WebUI 与统计接口

- 待处理页面保持当前详情能力，附件展示本地相对路径、下载校验状态、错误原因和摘要状态。
- 已办页顶部三个全库指标改为“OA 已办事项”“成功下载事项”“已验证附件”。移除“最近100项下载成功”和“最近100项附件”的最近窗口口径。
- 已办列表改为分页查询，不再把固定 100 条客户端数组当作全量数据；搜索、状态和页码均由服务端查询。
- 已办页提供“增量刷新”和“全量核对”操作。增量刷新固定扫描最新三页；全量核对使用现有全量任务端点，并显示当前任务进度与错误。
- 统计定义：OA 已办事项为清单记录总数；成功下载事项为已办清单中最终归档状态为下载成功且本地归档对象存在的事项数；已验证附件为已办归档中附件角色文件且校验状态为 verified 的文件数。正文不计入附件数，同一归档文件记录只计一次。

## 错误处理与恢复

- 待办列表刷新只有完整成功后才关闭缺失记录；登录失效、超时或解析失败时保留上一次当前态，避免误清空。
- 增量扫描只增加或更新已办，不以三页结果删除旧已办。全量核对支持断点续跑，失败后显示错误并允许重试。
- 下载成功必须以本地文件存在、大小及摘要校验通过为准。部分附件失败时事项不得计入“成功下载事项”，错误保留在附件和事项状态中。
- 资源繁忙时任务进入可恢复重试，不允许启动第二个持久浏览器上下文绕开租约。

## 测试与验收

- 合成待办先有 33 条活动记录、刷新仅返回 5 条后，接口和 WebUI 均显示 5 条；刷新失败时仍显示 33 条。
- 待办新增、内容变化、无变化、消失后重新出现均保持幂等，历史文件和摘要不被删除。
- 待办流水线依次产生已验证附件、Markdown 和 Ollama 摘要；通知关闭时任务完成且不出现 `PIPELINE_STAGE_NOT_IMPLEMENTED`。
- 严格身份匹配成功会关闭待办、创建已办关联并排入 `realtime_done`；字段不完整或冲突只生成一条复核记录。
- 三个已办指标使用超过 100 条的合成数据验证全库计数，并覆盖正文排除、附件失败、无附件和缺失本地归档对象。
- 增量刷新只请求三页；手动全量核对复用单一任务、可查看进度并可恢复失败。
- 运行后在真实本地环境只读刷新，核对 OA 当前待办数量、附件路径与 SHA/大小，不把任何真实数据写入测试夹具或 Git。
