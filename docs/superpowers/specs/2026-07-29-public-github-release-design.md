# OARadar 公开 GitHub 发布设计

## 目标

将当前 OARadar 应用整理为可公开发布的代码仓库，同时确保 OA 地址、导航参数、凭据、业务数据、运行产物、浏览器状态、内部实施记录和真实运行统计始终只保留在本机。

首次发布采用无历史的新 Git 仓库，许可证为 MIT。仓库名称优先使用 `OARadar`，不可用时使用 `oa-radar`，并创建在 GitHub CLI 当前登录的个人账号下。

## 发布边界

公开仓库跟踪：

- `src/` 应用源代码；
- 仅使用合成或不可逆脱敏数据的 `tests/`；
- `webui/` 前端源代码及应用运行所需的构建产物；
- 数据库迁移与通用 MinerU 容器配置；
- 面向公众的 README、架构说明和安全说明；
- 不含真实环境值的 `config.example.yaml`；
- MIT License；
- 发布安全检查脚本和持续集成配置。

以下内容只保留在本地且不得被 Git 跟踪：

- `data/` 中的 OA 元数据、正文、附件、解析结果、知识库、数据库、备份和报告；
- `config.yaml`、环境变量文件及任何真实 OA 地址或导航参数；
- 浏览器 profile、Cookie、Playwright 状态、页面快照、下载文件和 trace；
- 日志、缓存、虚拟环境和临时构建文件；
- 内部阶段报告、实施 Goal、真实运行规模、日期和部署状态记录；
- 个人工具配置和本机专用服务配置。

现有内部文档迁移到被忽略的 `private/` 目录。公开 `docs/` 只保留重新审阅后的通用文档，避免依赖逐个内部文件名的排除规则。

## 配置设计

应用的真实运行配置使用被忽略的 `config.yaml`。公开仓库只提供 `config.example.yaml`，其中 OA 基础地址、登录路径、待办路径、已办路径和站点特有参数均使用明显的合成占位值。

首次使用者复制示例配置后在本机填写环境值。`data_root` 默认使用本地 `./data`；数据库、归档、解析和报告路径保持相对于 `data_root`。OA 标识继续按文本存储，归档路径继续按相对于 `data_root` 的形式存储。

配置层继续拒绝密码、Cookie、Authorization、Token 和 Secret 等明文字段。凭据只允许从环境变量或本机浏览器凭据机制获取，不进入配置、数据库、日志或命令行参数。

## 数据流与安全边界

OA 集成保持只读，不增加批准、回复、删除、转发或修改 OA 记录的能力。运行时数据流为：本地配置提供连接参数，采集器只读访问 OA，产物写入本地 `data_root`，公开仓库不参与同步或托管任何采集结果。

容器树最多遍历 10 层。仍有子节点时必须入队 `depth_limit_reached`，不得将对应事项报告为完成。

远程模型调用仍受机密级别和脱敏门禁控制；公开示例默认采用本地模型和拒绝机密外发的设置。

## 防泄漏机制

### Git 忽略规则

`.gitignore` 必须覆盖真实配置、环境变量、`data/`、`private/`、数据库、日志、浏览器状态、Playwright 产物、下载文件、运行目录、知识库、缓存、虚拟环境和个人工具配置。

### 发布扫描

新增 `scripts/check_public_release.py`，扫描 Git 已跟踪文件或准备提交的文件，而不是扫描本地 OA 数据。检查至少包括：

- 非合成的 IP 地址、域名和 OA URL；
- 站点特有的长数字导航标识与查询参数；
- API Key、Token、Cookie、Authorization 和常见凭据格式；
- 用户目录等个人绝对路径；
- 真实业务数据特征；
- 禁止公开的文件名、扩展名和目录。

扫描器支持一份有解释的、范围尽可能小的合成值允许列表。任何未解释命中均以非零状态退出并阻止发布。

### 持续集成

GitHub Actions 在 push 和 pull request 上执行发布扫描、Python 测试和前端检查。扫描失败时工作流失败。

## 文档设计

公开 README 删除真实运行数量、内部日期、部署状态、真实网络信息和组织特有操作记录，改为包含：

- 项目定位与功能范围；
- 安装、初始化和本地配置步骤；
- OA 只读及本地数据边界；
- 本地模型与可选远程模型的隐私说明；
- 测试与发布安全检查方法；
- 当前通用能力和限制；
- MIT License 与使用免责声明。

另提供公开仓库安全边界文档，明确任何真实 OA 内容都不属于仓库资产，测试只能使用合成或不可逆脱敏 fixture。

## 验证策略

发布前必须完成：

1. 查看 Git 实际跟踪清单，确认没有本地私有内容；
2. 运行发布扫描及其针对敏感模式和允许列表的测试；
3. 运行完整 Python 测试；
4. 运行前端检查和生产构建；
5. 使用脱敏示例配置执行最小初始化；
6. 在临时目录模拟全新 clone 后的安装、构建和测试；
7. 检查提交 diff 和对象库中不存在禁止内容；
8. 推送后核对 GitHub 仓库为 public、默认分支正确且远端文件清单安全。

若任何检查命中疑似敏感信息，发布必须停止。只有人工确认该值为合成测试值后，才能添加带说明的最小允许规则。

## 首次发布流程

当前工作区没有 Git 历史，因此在本地运行数据不动的前提下初始化新仓库。先完成目录隔离、配置脱敏、文档整理、扫描器与测试，再显式暂存允许公开的文件。不得使用未经核对的全目录暂存。

所有验证通过后创建首个干净提交。通过 GitHub CLI 当前登录账号创建公开仓库，名称优先为 `OARadar`，重名时使用 `oa-radar`，然后推送默认分支。首次发布直接建立干净默认分支，不创建包含私有历史的 PR。

## 完成标准

- GitHub 仓库可公开访问并采用 MIT License；
- 仓库可在全新环境中安装、测试和构建；
- 用户必须自行在本地提供 OA 地址和站点参数；
- OA 数据和运行产物只写入被忽略的本地目录；
- Git 跟踪文件、提交对象和 GitHub 远端均不含真实 OA 信息或内部实施记录；
- OA 行为保持只读，深度限制和未完成语义保持不变。
