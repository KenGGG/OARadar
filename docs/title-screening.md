# 下载筛选与机构归档

## 简化排除优先模式

支持另一种独立规则规格：E01、E02、E03、E04、E05、E06、DEFAULT，依次首个命中生效，动作以规格的 `action` 为准。该模式仅做 NFKC 和空白折叠，不移除转发前缀；E05 支持 `CUSTOM_ADMIN_OR_PAYMENT`：规范化标题以“付款申请单”开头，或同时命中流程词和后勤用途词，即排除。其余默认下载，不使用旧保护词、不自动安排正文复核。已有原件和人工覆盖继续保留，机构与刊物分类独立执行。

该模式可能排除涉及项目放款、偿债、监管账户等事项的后续附件，是明确选择的规则范围，不代表这些材料没有价值。可以通过单项人工意见强制保留。

已办清单的分层筛选与原件下载、Markdown 转换、正式机构分类分别记录。启用筛选方案后，该方案接管已办清单的旧标题包含式黑名单；其他渠道仍遵循原设置。所有配置、建议和正文证据只保存在本机数据库中，不将交付表格或机构字典放进仓库。

## 规则与下载

优先次序：人工覆盖、正式制度和决策保护、核心业务保护、明确行政流程、项目融资风险保护、组合后勤排除、待复核、默认保留。匹配时规范全半角、空白和固定转发标记，原标题保持不变。未知附件数保持未知。

证件外借用途未核实，以及保险、年金、银行询证等用途存在歧义时，转为待复核。待复核默认继续下载。排除只控制后续抓取，不删除已经保存的原件；已验证原件可复用。已有人工排除优先，用户可记录依据后恢复标题规则。

页面“下载筛选与归档建议”可筛选、搜索、导出全部建议，也可逐项修改。人工意见保存修改前的值、修改依据和时间，重新同步时保留。新事项自动应用同一规则，事项ID全程作为字符串。

## 正文预览

“批量读取待复核正文与目录”创建独立任务，支持暂停和继续，复用浏览器登录及已经校验的本地正文。仅抓取正文页面与可见附件标签，不下载附件全文；关联容器尚未核验时，附件数量继续为未知。预览失败或用途不明不改变下载许可。正文中的业务保护线索仅产生建议，最终复核通过逐项意见完成。

## 归档与原件

标题提及的机构可能是客户或办理对象，不能当成发文单位；发起人不用于推定机构。文号映射也只是候选，正文落款和机构历史名称需要核实。刊物单列，业务简报、正式批示等保留文件属性。同一事项保持完整，不按附件拆散。

候选路径采用机构或刊物、发起年月、缩短标题和完整事项ID。未知机构进入待确认组。人工核实来源后可以修改目录并确认分类；待确认路径不能确认为正式目录。

“生成已确认目录索引”在 `data/runtime/organization-index` 中生成一次独立目录索引，`current.json` 指向本次结果。索引包含完整标题、事项ID及规范原件位置，不移动、不重复复制原件。重新生成使用新的运行目录，历史索引不会混入当前结果。尚未确认、或已排除的事项不会发布索引。这与现有原件镜像的 Markdown 转换是独立流程。

## 本地导入

日常微调在“系统设置 → 已办下载筛选规则”完成：展开规则修改开关、标题表达式或说明，组合条件在流程词与用途词区修改。付款申请单的无条件匹配表达式留空表示取消该分支。修改后预演全部当前清单，核对数量和变化示例，再保存启用新版本。规则单独保存且立即生效，顶部按钮仅保存通用设置。

每次微调生成新版本，保留历史规则并支持恢复；已有人工覆盖和原件保留。采集任务运行时无法保存规则，避免途中切换方案。默认保留规则不可关闭，非法或空匹配表达式无法保存。编辑时如果当前方案已被其他窗口改变，会要求重新读取。

开发或管理员可通过 `oa_knowledge.title_screening.import_spec(settings, spec_path)` 导入本地 JSON 规则规格，通过 `view(settings, plan_id=...)` 预演，经核对后使用 `set_active(settings, plan_id)` 启用。导入不启动网络采集、不移动文件。运行中的任务必须先暂停，才能修改方案或人工意见。

规则规格仅接受规定的保护顺序和规则类型，原交付件的固定统计量用于离线核对，不作为未来事项总数上限。
# 五类归档分类

第二轮补充规则仅在基础分类仍为 UNKNOWN 且保留下载时匹配。规则按声明式条件顺序运行，支持开关和表达式微调；不执行外部 Python 脚本。既有分类、人工意见、排除决定和原件位置保留。缺明确来源的人事任免、普通学习资料和扩展活动规则保持待确认。

外部来文的主题归集使用 `archive_bucket`，不写成发文机构；状态为 `source_pending`，`needs_review=true`。联合来源保留标题来源段、匹配机构列表和来源关系；多文合办标记为 `multiple_documents`，不冒称联合发文。标题来源与正文或人工核实分别记录，机器标题归类不设置来源已核实。第二轮规则可以在系统设置逐条停用、预览、调整及恢复历史版本。

五类分类独立于下载筛选，仅对保留下载事项生效。机构字典及版本保存在本地数据库，不提交真实机构配置或事项内容。

目录为 `01_本公司资料/年份/OA_ID`、`02_集团及成员企业/机构/年份/OA_ID`、`03_外部机构来文/机构/年份/OA_ID`、`04_刊物与学习资料/系列/年份/OA_ID`、`99_待确认/年份/OA_ID`。年份优先使用发起时间，其次处理时间，缺失记为年份待确认。这里是逻辑路径，原件仍保留原位，不移动、不重复复制。

具名刊物优先；明确正文发文单位高于唯一正式文号，高于标题起始段发文主体。OA 发起人、转发者、客户名称及标题中间提及的机构不作为来源。来源冲突或未匹配机构进入待确认；普通学习材料不自动认定为刊物。本公司业务流程按指定标题表达式识别。

系统设置中的“五类归档分类规则”允许微调业务流程、发文机构、文号前缀和刊物系列表达式。编辑后先预览，保存产生新版本，可从历史恢复。下载清单支持按归档类别筛选，导出包含分类版本、规则、映射、来源、依据及待确认标记。人工分类意见继续保留；生成已确认目录索引仍只发布人工已确认事项。
