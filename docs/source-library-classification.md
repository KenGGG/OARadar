# OA 资料库五类来源规则

附件筛选、来源分类、搜索标签是三个独立阶段。来源分类不决定附件价值，文件类型和业务主题不生成目录。

## 目录

- `01_本公司资料/年份/发起日期_OA原标题/`
- `02_集团及成员企业/机构/年份/发起日期_OA原标题/`
- `03_外部机构来文/区域/发文机构/年份/发起日期_OA原标题/`
- `04_刊物与学习资料/固定系列/年份/发起日期_OA原标题/`
- `05_待确认/年份/发起日期_OA原标题/`

保留原标题文字与标点，只替换 Windows 非法字符、裁剪路径过长部分。同日重名或裁剪后重名时，按持久化记录顺序追加 `_2`、`_3`，不以 OA 数字 ID 命名。完整标题、发起日期、发起人及文本形式的 OA ID 均保存在附件 Markdown 元数据中。日期使用事项发起日期，缺失时明确写“日期待确认”，不使用附件日期冒充。

外部区域固定为黄埔区、广州市、广东省、其他机构。具体发文单位保存在 `archive_organization`、`source_organizations` 中。多个已识别的外部发文单位可归外部联合来文；跨来源类别冲突仍待确认。

机构层通过本地 `external_routing.agency_labels` 统一目录称呼，例如区委组织部、工业和信息化局、国资委、金融部门。实际发文机关全称保留在元数据中，目录机构标签写入 `archive_agency`。同一地区联合发文使用“联合发文”；跨地区联合发文使用“其他机构/联合发文”。

`【文件传阅】` 是优先归入外部来文的标题线索，处理顺序仍先排除下载、再识别固定刊物与可靠的本公司/集团来源，最后对仍未知的传阅事项应用外部归档。机构尚未核实则暂放“其他机构/机构待确认”，保留 `needs_review=true`，不把机构猜测当作已核实。

标题末尾的 `（由某人原发）`（兼容半角括号）采用相同的外部来文兜底规则，仅作用于尚未识别来源且无来源冲突的事项。该标记说明转发链路，不代表原发人的所属单位就是发文机关。明确的本公司、集团、固定刊物证据优先；具体机构由正式标题、文号及正文落款核实，不能从姓名猜测。政府“中心”“研究室”等完整发文标题也参与机构识别。

政府机构识别结合正式标题、附件名称、正文落款和印发单位，忽略引用、抄送与收文对象。企业名称即使带“广州开发区”等地名，也不能识别成政府机关；集团党委、纪委、工会、办公室仍归所属集团。发起人不单独决定来源。

本公司具名董事会、监事会、办公会材料与业务报告，按事项主体归本公司；随附的上级规定、参考材料中的发文机关保留为附件证据，不因此把整个事项判为多来源冲突。集团专题会议纪要可由附件主文页首的完整集团名称识别，不要求页尾一定有日期落款。只有正文中提到某企业或作为合同对方出现时，不应用这条规则。

内部事项呈批、董事会/办公会议题申请、项目预审和租后报告属于本公司办理流程；转发、传阅和原发标记阻止这组新增流程规则直接套用。第一议题、党员和主题党日学习资料须同时有明确学习材料标题和实际理论学习正文，才归“主题党日与专题学习资料”；签到表、会议安排或空表不满足条件。

## 判断

优先识别已登记的固定刊物，然后识别本公司实际办理的流程、集团成员和外部机构。普通内部工作简报不因“简报”二字归刊物。

正式文件使用明确落款、正式文号、明确发文标题作为证据。读取附件自己的名称和经过哈希验证的有效 ParseArtifact；正文中提到的机构、引用的文号、OA 发起人不等于发文单位。新增解析证据会使缓存失效，下一次发布重新判断来源。

主文标题起始的正式集团文号优先确定整个事项来源：`穗凯金服` 对应“凯得金服”，`穗开控股` 对应“广开控股”。可忽略开头“【公告】”等显示标记，兼容标准文号以及“〔年份〕序号-”这种缺少“号”字的旧标题。附带的监管规定、上级参考通知不因此构成事项来源冲突。事项标题不明确时，可使用附件自身标题或已校验正文页首的唯一集团文号；多个不同主文文号仍保留复核。“根据某文号”等引用及本公司内部办理事项不能仅因参考文号而转为集团资料。下载筛选仍先于此规则。

外部主文文号也优先于随附参考文件的来源。支持文号位于标题开头，或“通知/通报/函”等正式标题末尾的括号中，例如“关于印发某指引的通知【穗埔组通〔2024〕16号】”。`穗埔组通`、`穗埔组干`、`穗埔组` 均对应黄埔区委组织部；`穗开组通`、`穗开组干`、`穗开组` 对应广州开发区工委组织部。前者目录为“黄埔区/区委组织部”，不能把附表、参考材料中的机构当成共同发文主体。

同一传阅事项包含多个已登记刊物系列时，按标题中最先明确出现的系列归档，其他系列写入 `related_publication_series`，全部附件保持在同一个事项文件夹。例如“老城市新活力工作简报＋干部作风与营商环境专项简报”归“老城市新活力工作简报”。若两个系列的识别位置重合而无法确定主次，仍保留复核；不会仅因标题含两个刊物名称就一律退回待确认。

机构字典、文号、固定刊物系列和公司流程表达式保存在本地启用的 `ArchiveClassificationPlan` 中，真实 OA 配置不得提交 Git。

## 附件筛选

下载筛选是整个处理流程的第一道门槛。先按已确认的六组排除规则 E01—E06 顺序匹配，命中立即结束，只保留标题记录；全部未命中才默认下载。分类优化只能处理通过筛选的事项，不能修改筛选结果。

当前恢复使用原始排除优先方案：请休假与离穗报备、差旅接待与通用报销、离职交接与申请、同名账户资金划转、付款申请单与日常行政采购付款、证件外借。付款申请单在标题任意位置命中。具体表达式与开关以本地启用的 TitleScreeningPlan 为准，独立于 ArchiveClassificationPlan。

简化筛选模式不执行 `protected_value_pattern`；项目、合同、放款、风险、制度等词不能把已排除事项重新纳入。转换、解析入队和 Markdown 发布入口再次检查筛选资格，防止旧任务绕过筛选。

筛选控制后续附件获取；已有归档原件作为不可变事实保留。排除事项不纳入新的活跃知识交付。

## 标签与交付

任免通知、合同协议、财务报告等只写入 `tags` 和 `document_type`。同一 OA 事项的附件共用来源目录，每份附件各有一份 Markdown，图片保存在同名 `.assets` 目录。当前方案启用 `delivery.attachments_only`，不生成 `_index.md`，无附件事项只留数据库记录，不创建空的事项文件夹。标签的不确定性与来源的不确定性分别记录。

`delivery_status` 依据实际附件转换与来源状态计算，不以存在索引为成功条件。层级超过 10、下载失败、附件缺失或转换失败均不能因分类完成而标记原件完整。

迁移只处理 Markdown 派生物。旧索引与改名前的 Markdown 保存在本地运行目录中；图片资源随派生文档迁移，并记录旧路径、新路径及哈希。原件路径与记录保持原样。

## 小批量优化来源分类

1. 仅对通过下载筛选的事项取样。按“发起人、标题模式、年份、是否已解析”分层，每轮抽取约 30—50 项，避免只读近期或同一人的资料。
2. 阅读事项所有已转换附件的标题、文号、正文主文落款与印发单位，附件表格与引用段落分开核对。签章可出现在正文中段，后面可能还有多页附表；不能只看全文末尾。
3. 记录真实来源类别、具体机构、证据位置和冲突。未解析、只有空白表格或无法核实来源的事项单列，不用猜测结果作为训练标签。
4. 优先补可解释规则：机构别名、正式文号、固定学习资料系列、本公司办理事项的标题表达。发起人只作样本分层和辅助证据，不单独决定来源；同一人可同时转发政府、集团和本公司文件。
5. 按事项分离规则开发样本与留出验证样本，覆盖不同年份；每条新增规则记录覆盖数、正确数和冲突例。只有正文证据一致的模式才扩大应用，出现跨来源冲突则保留待确认。
6. 每轮输出新增可靠归类数量、剩余待确认数量、无可用正文数量，以及规则误判/冲突记录。目标是减少真实不确定性，而不是用默认归类清空“待确认”。

真实机构字典、发起人统计、样本文本和迁移记录均仅保存在本地运行目录或数据库，不提交版本库。

## 剩余附件转换

本机隔离的 LibreOffice 处理旧版 Word、Excel，以及包含图片的 Word、PowerPoint；仅打开缓存中的副本。Word 和演示文稿转为 PDF 后交本机 MinerU OCR，旧表格转为 XLSX 后提取正文。原件、OA 标识和下载筛选结果不改变。

ZIP、RAR、7z 按成员逐一提取正文，汇总到与压缩包附件对应的一份 Markdown，图片资源保持本地引用。成员有不支持、加密、损坏或转换失败时，整包不记成功；目录深度最多 10，超过上限进入 `depth_limit_reached` 复核队列。视频等不能完整转换的格式记录问题，不以附件列表或元数据冒充全文。
