# 在线已办审计设计

## 目标

提供独立、持久、只读的在线审计：遍历当前全量已办清单，逐项访问 OA 详情页，比较 OA 识别附件、本地成功下载和成功 Markdown 化数量，并记录访问错误与耗时。

## 数据模型

`online_audit_runs` 保存一次审计的总状态、目标数、各结果计数和时间；`online_audit_items` 保存每个事项的 OA/下载/Markdown 数量、状态、错误码、脱敏错误和耗时；`online_audit_events` 保存可展示的结构化实施日志。一个运行只对应每个事项一条结果。

## 执行与暂停

开始操作创建运行、事项快照和 `online_audit` OperationJob。单一后台 Worker 复用现有 BrowserSession、DoneAdapter 和 CollaborationDetailAdapter，以只读方式访问详情。每完成一项持久化结果后检查 `pause_requested_at`；如存在则安全进入 paused。继续操作重新排队同一任务，从 pending 项继续。服务中断后租约恢复机制将运行置为可继续状态。

审计不归档、不下载写盘、不修改事项处理状态，不触发 Markdown 转换。附件识别使用详情采集结果；下载数量读取数据库 verified 文件；Markdown 数量读取成功导出账本。

## Web 页面

新增“审计”一级导航。页面展示开始、暂停、继续按钮，总进度与累计耗时，当前事项，每项核对结果，OA 错误汇总和时间倒序实施日志。页面轮询刷新。日志只保存结构化阶段、错误码和脱敏摘要，不保存 Cookie、Token、账号或完整响应。

## 错误与测试

认证过期、详情访问失败和不支持页面分别记录稳定错误码，单项失败不终止全批次。测试使用合成数据库和假详情检查器，覆盖创建、单例约束、计数、耗时、暂停/继续、错误脱敏、API 状态和 Worker 路由；测试不连接真实 OA。
