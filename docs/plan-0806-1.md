
# OARadar 自动运行功能端到端修复任务

## 一、任务目标

基于当前 `main` 分支进行修复，不再增加新的概念性模块。必须使以下四条链路在真实 Ubuntu 环境中完整运行：

```text
1. 定时刷新待办
2. 新增或变化待办生成摘要并发送飞书
3. 定时刷新已办并下载归档
4. WebUI显示、控制并验证上述运行状态
```

最终用户不得再依靠查看代码、执行多个零散命令或阅读数据库判断系统是否运行。

# 二、P0：修复当前明确存在的错误

## 1. 修复 CLI 命令注册顺序

文件：

```text
src/oa_knowledge/cli.py
```

将：

```python
if __name__ == "__main__":
    app()
```

移动至文件最末尾，确保以下所有命令完成注册后才启动 Typer：


```bash
python -m oa_knowledge.cli schedule --help
python -m oa_knowledge.cli notifications --help
python -m oa_knowledge.cli knowledge --help
```

这些命令必须返回 0。

## 2. 修复 Web 手动触发命令

文件：

```text
src/oa_knowledge/web/schedule_views.py
```

将：

```python
run_cli([stage], ...)
```

修改为：

```python
run_cli(["schedule", stage], ...)
```

禁止继续使用：


Web 请求必须建立持久化任务：


```json
{
  "job_id": 123,
  "status": "queued",
  "stage": "hourly"
}
```

不得在没有确认任务成功入库时返回“已触发”。

# 三、P0：重新实现新增已办归档链路

## 1. 当前错误链路

禁止继续采用：

```text
新增已办
→ attachment_inventory
```

`attachment_inventory` 只适用于已经下载完成的事项。

## 2. 正确链路

新增队列阶段：

```text
realtime_done
→ done_detail_sync
→ done_archive
→ attachment_inventory
→ parse
→ markdown_export
→ completed
```

或者合并为：

```text
realtime_done
→ done_capture_and_archive
→ attachment_inventory
```

## 3. `done_detail_sync` 应完成

```text
1. 根据 OAManifestItem 获取 workitem_id
2. 获取 OA 浏览器资源租约
3. 检查 OA 登录状态
4. 打开已办详情
5. 抓取正文、流程、意见和附件
6. 下载并校验附件
7. 调用 archive_collaboration_detail
8. 更新 OAItem 和 OAManifestItem
9. 将验证通过的文件加入 MarkdownTask
10. 推进到 attachment_inventory
```

应复用现有：

```text
CollaborationDetailAdapter
archive_collaboration_detail
archive_proxy
verified_attachment_resolver
enqueue_verified_for_oa
```

不得重复开发另一套归档代码。

## 4. 幂等要求

幂等键至少包含：

```text
realtime-done:<oa_item_key>:<discovery_hash>:archive-v2
```

以下情况下不得重复下载：

```text
OAItem已经完整归档
附件SHA256已经验证
OAManifestItem归档状态已经成功
```

归档不完整或附件失败时允许建立新版本重试。

# 四、P0：消除 SQLite 嵌套写事务

当前调度代码在一个 `Session` 未提交时，调用会另开 Session 的：

```python
enqueue_realtime_done(engine, ...)
```

这可能导致 SQLite 写锁冲突。

修改原则：

```text
一个业务步骤只使用一个写 Session
```

将函数改为支持：

```python
enqueue_realtime_done(
    session=session,
    oa_item_key=...,
    manifest_id=...,
)
```

不得在外层 Session 未结束时另开写 Session。

同时删除：

```python
_session_for(engine)
```

不要为每个已办事项创建一个不关闭的 Session。

应在一次查询中预加载本地已知事项及其哈希：

```python
known_items = {
    row.oa_item_key: row.discovery_hash
    for row in ...
}
```

之后在内存中判断已知边界。

# 五、P0：让定时运行真正可安装和可检查

## 1. 安装程序

修复：

```text
scripts/install-systemd-user.sh
```

必须完成：

```text
检测当前Git提交
构建WebUI
验证Python依赖
验证数据库
渲染systemd unit
安装worker
安装markdown-worker
安装hourly timer
安装nightly timer
启动服务
检查服务状态
输出下一次运行时间
```

脚本中不得使用未解析的：

```bash
uv run
```

统一使用检测到的：

```bash
"$UV_BIN" run
```

## 2. 增加 Web 服务 unit

增加：

```text
oaradar-web.service
```

安装程序必须同时管理：

```text
oaradar-web.service
oaradar-worker.service
oaradar-markdown-worker.service
oaradar-hourly.timer
oaradar-nightly.timer
```

这样更新代码后可以统一：

```bash
systemctl --user restart oaradar-web.service
```

避免后台运行旧 Web 进程。

## 3. 安装后强制检查

安装程序最后执行：

```bash
systemctl --user is-active oaradar-web.service
systemctl --user is-active oaradar-worker.service
systemctl --user is-active oaradar-markdown-worker.service
systemctl --user is-enabled oaradar-hourly.timer
systemctl --user is-enabled oaradar-nightly.timer
systemctl --user list-timers 'oaradar-*'
```

任何一个失败，安装脚本返回非零。

# 七、待办与飞书端到端要求

正确流程：

```text
定时扫描全部待办
→ 比较discovery_hash
→ 新增或实质变化才建立任务
→ 抓取详情和附件
→ 解析附件
→ 生成结构化摘要
→ 建立NotificationDelivery
→ 飞书发送
→ 记录sent
```

必须确保：

```text
存量基线不通知
新增待办通知一次
不变待办不通知
节点、截止时间或正文变化后通知新版本一次
发送失败可见
配置错误可见
OA登录失效可见
```

WebUI 待办列表增加：

```text
最近发现时间
最近摘要时间
飞书通知状态
最近通知时间
通知失败原因
```
