## 一、必须遵循的产品定位

OARadar 只承担以下三项工作。

### 1. 待办监控与飞书通知

```text
定时扫描 OA 待办
→ 采集当前待办内容
→ 使用模型生成摘要和待处理事项
→ 发送飞书
→ 飞书确认发送成功
→ 删除待办正文、附件、快照、摘要等业务内容
→ 只保留防止重复通知所需的最小台账
```

待办数据不是永久知识资产。

待办内容成功发送飞书后，应按照配置自动清理，避免长期保存业务正文和临时附件。

### 2. 已办附件永久归档与 Markdown 转换

```text
定时扫描 OA 已办
→ 识别所有附件
→ 下载并验证附件
→ 永久保存原始文件
→ 生成 Markdown
→ 保留 OA 事项、原始文件和 Markdown 的来源关系
```

原始附件是永久事实底稿，默认不得删除和覆盖。

Markdown 是可重新生成的派生产物。

### 3. 向 llm_wiki 交付 Markdown

Markdown 生成后，由 OARadar 输出到外部 `llm_wiki` 项目的来源目录，例如：

```text
<llm_wiki项目>/raw/sources/oa/
```

后续由以下项目完成知识加工：

```text
https://github.com/nashsu/llm_wiki
```

最终知识库由 llm_wiki 生成，并通过 Obsidian 查看。

OARadar 不负责：

* 建设 Wiki 页面；
* 维护知识图谱；
* 提供知识问答；
* 建设实体、概念和主题页面；
* 管理 llm_wiki 的知识生成任务；
* 替代 Obsidian。

# 六、待办数据清理机制

这是本次必须实际落地的核心功能，不能只修改页面。

## 6.1 清理触发条件

只有在飞书服务明确返回发送成功后，才能自动清理业务数据。

以下状态不能自动删除：

```text
发送失败
等待重试
请求超时且结果未知
飞书配置异常
OA 数据仍在摘要处理中
```

对于 `unknown_outcome`，不得自动重发，也不得清理，必须等待人工确认。

## 6.2 默认清理内容

飞书发送成功后，根据配置清理：

* OA 待办正文；
* 流程意见文本；
* 页面 HTML 或 JSON 快照；
* 临时附件；
* 附件解析结果；
* 模型输入正文；
* 摘要正文；
* 结构化摘要详情；
* 飞书卡片正文副本；
* 临时文件。

## 6.3 最小去重台账

清理后必须保留不含业务正文的最小台账，用于防止重复通知。

至少保留：

* OA 稳定事项 ID；
* 内容版本哈希或 discovery hash；
* 首次发现时间；
* 最近发现时间；
* 成功发送时间；
* 发送状态；
* 通知消息指纹；
* 清理完成时间；
* 脱敏错误码；
* 是否允许重新通知。

最小台账默认不应保留：

* 标题；
* 发起人；
* 正文；
* 摘要；
* 当前节点；
* 附件名称；
* 附件内容。

如现有表结构不适合，请增加迁移或独立的最小台账模型。

优先复用现有模型，但不得因为复用而继续永久保留业务内容。

## 6.4 清理状态

增加明确状态：

```text
not_eligible
pending_cleanup
cleaning
cleaned
cleanup_failed
```

并记录：

* `cleanup_requested_at`
* `cleaned_at`
* `cleanup_error_code`
* `cleanup_attempts`

## 6.5 保留策略配置

增加配置项：

* 飞书成功后是否自动清理；
* 成功后立即清理或延迟若干小时；
* 飞书失败数据保留天数；
* 是否保留摘要正文；
* 是否保留页面快照；
* 是否保留临时附件；
* 是否允许人工清理已经确认 `sent` 的数据；该开关不得绕过发送成功门禁。

默认配置：

```text
发送成功后立即清理
不保留摘要正文
不保留页面快照
不保留临时附件
仅保留最小去重台账
```

如未来增加删除同步，必须单独配置，并默认关闭。

# 十三、测试要求

必须补充真实测试，不能只测试前端字符串或 mock 整个业务函数。

## 13.1 待办成功通知与清理

测试完整链路：

```text
发现新待办
→ 生成摘要
→ 飞书返回成功
→ 清理任务执行
→ 业务正文、快照、临时附件和摘要被删除
→ 最小去重台账仍存在
→ 再次扫描相同版本不会重复发送
```

## 13.2 发送失败不得清理

测试：

```text
飞书发送失败
→ 数据仍保留
→ 状态为等待重试或失败
→ 不执行清理
```

## 13.3 unknown_outcome 不清理、不自动重发

验证：

* 不删除业务数据；
* 不自动再次发送；
* 普通重试接口拒绝再次发送；
* UI 显示“发送结果待确认”，且不显示重发或清理按钮。

## 13.4 已办原始附件不可变

测试：

* 原始文件成功归档；
* Markdown 重建不会修改原始文件；
* 原始 SHA256 保持一致；
* 重复转换不会创建重复永久原始文件。

## 13.5 Markdown 原子交付

测试：

* 先生成临时文件；
* 最终目标只出现完整文件；
* llm_wiki 来源目录不可写时返回稳定错误；
* 重试成功后状态变为已交付。
