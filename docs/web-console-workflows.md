# 三流程控制台

控制台沿用现有数据库、任务队列及 Worker。原件归档结果与 Markdown 交付结果独立展示；索引生成成功不再代表所有附件已交付。

## 页面与操作

| 页面 | 主要能力 |
| --- | --- |
| 总览 | 待办通知、已办原件、Markdown 三张状态卡；首次运行、停用与异常状态；告警跳到对应筛选结果 |
| 待办通知 | 服务端搜索、筛选与分页；摘要和阶段详情；失败摘要/投递重试；符合条件的本地清理；投递结果核对 |
| 已办资料 | 原件清单、大小、哈希、校验时间；归档恢复；与 Markdown 详情互相跳转 |
| Markdown 输出 | 按事项搜索、状态筛选与分页；附件成功/应交付数量；文件与索引详情；纯文本预览、下载和本地重新生成 |
| 系统设置 | PATCH 保存；显示已保存但等待重启的配置；保护未保存编辑；本地可选认证登录 |

分页、筛选和选中事项写入 URL hash，刷新后保留。列表与详情定期更新，接口失败会展示错误；详情读取失败时停止提供恢复操作。

## 状态与恢复边界

- 附件失败、缺件、不支持转换、分类待复核、旧哈希产物均不能算完整交付。
- 容器深度达到上限仍需处理，不能标记完成。缺少明确无附件确认的空清单需要重新核对归档。
- 重试原件走已有的只读 OA 采集队列；重试 Markdown 只走本地交付队列，复用有效解析产物。
- 连续或并发提交会复用已有在途任务；不可恢复的任务和分类复核边界不能被通用重试绕过。
- 飞书投递结果未知时不能直接重发。用户在飞书核对后，可明确登记已收到或未收到；登记只更新本地台账，不自动发送或清理。
- 已清理待办的接口与页面均移除正文、附件、摘要、标题和发起人；不通过详情查询恢复业务内容。
- 原件下载与 Markdown 预览按数据库标识查找，使用受保护的本地路径，拒绝路径越界及符号链接。预览以文本显示，不执行文档中的 HTML。

## 验证

全部验证使用合成数据。应用运行中的配置、数据库、真实 OA、飞书和模型服务不参与这些测试。

```bash
uv run pytest
cd webui
npm run check
npm run build
```

构建后，在仓库根目录显式启用浏览器测试：

```bash
OARADAR_BROWSER_TESTS=1 uv run pytest tests/test_webui_workflows.py
```

浏览器测试使用本机 `/usr/bin/google-chrome`；其他安装位置通过 `OARADAR_TEST_CHROME` 指定。测试启动临时 loopback 静态服务器，拦截 API 为合成响应，并阻止外部请求。

关键回归：`test_simple_delivery_facts.py`（完成条件）、`test_workflow_console.py`（持久化、并发、清理边界与安全读取）、`test_webui_workflows.py`（实际页面点击与移动布局）。

代码及静态资源更新后，需重启 Web 服务加载新的后端接口。设置变更需要对应运行服务重启后生效，控制台会显示这一状态。
