# 分类优化实施记录

目标：内部按六类业务主题展示，外部按实际发文机构；保留历史数据库编码与路径。

本次使用本地清单、历史数据库快照进行离线诊断，不把历史快照称为当前生产分类准确率。真实标题、人员与事项标识未写入本文或测试。

## 已实施

- 四份私有配置位于 `private/classification/`，保持 0600 权限。人员身份和机构映射保留，补充使用边界说明；四组文号改为年份括号与序号的严格格式；合同审批模板取消固定业务分类。
- 文号收集全部配置候选，引用语境不作为主文号，多个候选不返回首个规则。
- 来源锁定不使用书名号内被引用的表单词；文号及明确发文主体阻止人员弱线索抢占来源；本公司传阅文件优先采用主体证据。
- 机构名称精确规范化，保留原始主体；多主文件冲突进入待确认。
- 细化财务审计、项目采购与诉讼、经营考核、薪酬制度等交叉主题。
- 新增六类聚合函数及单事项展示接口字段 `internal_display_group`。旧风险合规、对外报送、其他类别需主题证据；未知不能归综合信息。

## 离线覆盖对比

本地已完成旧规则与严格规则的覆盖比较，并按文号字头抽样核验正式文件抬头及落款。严格规则拒绝未确认派生字头与不配对年份括号；抽样按解析文件哈希去重，避免把重复事项误算为独立证据。业务数量、真实字头、人员与样本证据仅保存在本地私有报告中。

## 验证和边界

私有配置仅采纳具有多份独立文件证据支持的精确字头。证据不足、OCR错误及格式异常样本继续待核验。私有核验记录位于被Git忽略的 `data/reports/`，未改写生产分类结果。审阅者可检查 `tools/audit_classification_boundaries.py` 的只读数据库访问、来源和产物哈希校验、抽样及私有输出逻辑；真实字头通过本地命令参数提供。

分类配置、元数据、逐项分类、内部分类、分类服务与解析缓存共 165 项回归测试通过。显式启用仅使用合成 HTTP 响应的本地浏览器测试后，14 项 WebUI 测试通过；这些测试覆盖现有页面工作流，不代表六组导航已实现。

未重分类生产数据库、迁移目录、下载附件、运行 OCR 或调用模型。现有人工锁定与排除流程未修改。六类字段已提供给展示接口，完整页面六组导航尚未实施。尚需核验派生字头、用主附件验证真实样本，并完成基础元数据层和细化层的全面优先级统一、增量重判范围控制及联合发文检索后，才能宣称整份优化方案完成。
