# OARadar 极简 WebUI 设计规格

**日期：** 2026-08-17
**状态：** 用户已确认方向，供后续模型实施
**替代范围：** 本规格仅替代既有 WebUI 信息架构与展示方式，不替代 OA 采集、原件保护、Markdown、Curated、飞书、在线核验和数据治理后端能力。
## 1. 背景与问题

当前 WebUI 把在线核验、六阶段流水线、Source Markdown、人工复核、数据治理、任务队列和服务维护同时暴露给日常用户。信息虽然完整，但用户很难直接回答两个真正关心的问题：

1. OA 已办有没有同步下来、附件有没有保存、有没有完成 Markdown 和最终归类？
2. 待办是否按时检查、飞书是否发送成功、本地模型有没有失败或使用兜底？

现有页面还容易把“原件已下载”“已有 Source Markdown”“已进入编目”和“已经发布到最终知识目录”混为一谈。新版必须使用结果语言，不要求用户理解内部队列和技术状态。

## 2. 产品目标

默认 WebUI 只回答两条业务链路的结果，并在确有异常时告诉用户是否需要处理：

- **已办知识库：** 同步 → 原件归档 → Markdown → qwen3.5:9b 归类 → 发布知识目录。
- **待办提醒：** 每小时扫描 → 下载证据 → qwen3.5:9b 摘要 → 飞书发送 → 临时资料清理。

默认一级导航固定为：

1. **总览**
2. **已办资料**
3. **系统设置**

在线核验、Source Markdown 明细、人工复核、数据治理、任务队列和服务诊断不删除，但统一收进系统设置中的 **高级维护**，默认折叠。

## 3. 非目标

- 不修改 OA 线上数据；所有 OA 集成继续严格只读。
- 不改变现有扫描、下载、解析、归类、飞书和清理业务逻辑。
- 不在本次工作中解决存量队列速度、解析器覆盖率或归类质量问题。
- 不删除现有后端 API、数据库表或高级维护能力。
- 不把 OA 正文、附件内容、完整标题、凭据或浏览器会话写入新状态接口和运行日志。
- 不把“已下载”或“已有 Markdown”误报为“知识库已完成”。

## 4. 核心业务口径

### 4.1 已办事项的简化状态

每个已办事项只显示一个主状态，按以下优先级计算：

1. **需要处理**：当前事项存在不可自动恢复的下载、解析、发布或归类失败，或者 Curated 状态为 `needs_review`。
2. **已完成**：事项原件已经验证；至少存在一个有效 Source Markdown；最新 Curated 运行完成；该运行的全部决策均为 `published`，且至少有一个发布决策。
3. **等待归类**：原件已经验证并且至少存在一个有效 Source Markdown，但尚未达到“已完成”。
4. **等待 MD 化**：原件已经验证，但没有有效 Source Markdown。
5. **等待下载**：尚未达到原件完整状态。

`depth_limit_reached` 永远属于“需要处理”，不得显示为已完成。

“原件已经验证”包括 `OAManifestItem.processing_status` 为 `downloaded` 或 `no_attachment`。`skipped` 必须显示为“已按规则排除”，不计入已完成知识库，也不计作系统错误。

### 4.2 已办汇总口径

总览必须分别展示以下事实，不能用一个百分比掩盖差异：

- OA 已办总数；
- 已完整归档事项数；
- 已按规则排除事项数；
- 确认无附件事项数；
- 至少有一个成功 Source Markdown 的事项数；
- 最终知识目录发布完成事项数；
- 整理排队、运行、失败、待复核事项数；
- 最近一次已办扫描时间。

首页大白话结论按事实生成：

- 全部完成：`已办知识库已完成：共 N 项，已归档并发布 N 项。`
- 尚未完成：`已办知识库尚未完成：已同步 N 项，M 项原件完整，P 项完成最终归类，Q 项仍在排队。`
- 有异常：在尚未完成文案后追加 `其中 R 项需要处理。`

### 4.3 待办和模型口径

待办卡必须展示：

- 扫描频率的人类可读文本，例如“每小时 05 分检查”；
- 最近扫描、下次计划执行时间；
- 最近一次 OA 待办数量；
- 飞书累计成功、失败数量和最近成功时间；
- 本地模型成功摘要数；
- 确定性兜底摘要数；
- 摘要失败或仍在重试数量；
- 当前使用模型，例如 `qwen3.5:9b`。

模型结论必须诚实区分：

- `正常`：没有失败、没有兜底；
- `正常，但使用过兜底`：飞书链路完成，但至少一个摘要不是模型正常输出；
- `需要处理`：存在摘要失败、飞书失败或未知发送结果。

不得把 `deterministic-fallback` 计入 qwen 成功数。

## 6. 页面设计

### 6.1 总览

总览默认只展示三张大卡：

1. **已办知识库**：一句大白话结论、五个关键数字、最近扫描时间，以及“查看已办资料”。
2. **待办飞书提醒**：扫描频率、最近/下次扫描、飞书结果、模型结果。没有错误时不显示技术细节。
3. **OA 后台状态**：未登录、正在登录、正在读取 OA、已退出四类状态。

页面顶部只有一个总体结论：

- `系统运行正常，但已办知识库仍在建设中。`
- `系统运行正常，两条业务链路均已完成当前任务。`
- `有 N 项需要处理。`

“需要处理”区域只列聚合问题和明确动作，例如“2 项 Source Markdown 无法生成，进入高级维护查看”。不得直接展开几十条复核明细。

### 6.2 已办资料

保留分页和搜索。默认表格列缩减为：

- 事项标题；
- 办结时间；
- 原件数量；
- 当前状态；
- 最后更新时间。

筛选器只保留：全部、等待下载、等待 MD 化、等待归类、已完成、需要处理、已按规则排除。

点击事项后打开简化详情，只显示：

- 当前做到哪一步；
- 原件是否完整；
- Markdown 是否存在；
- 是否完成归类发布；
- 如果失败，用中文说明原因；
- 本地归档目录和知识目录仅在“查看技术详情”折叠区显示。

默认界面不显示六阶段色条、哈希、解析引擎、任务 ID、幂等键、租约、在线核验证据和单独的 Source Markdown 大表。

### 6.3 系统设置

默认区只保留：

- 待办扫描：启用状态、频率、最近/下次执行；
- 已办扫描：增量扫描和夜间全量扫描状态；
- 本地模型：是否可用、当前模型；
- 飞书：是否已配置、最近成功和失败；
- 服务：Web、Worker、Markdown Worker 是否运行。

下方提供一个默认关闭的 **高级维护** 折叠区。展开后承载现有：

- 在线逐项一致性核验；
- Source Markdown 人工复核；
- Source Markdown 输出表；
- 任务队列；
- 数据治理；
- 完整性调查、清理、隔离与恢复；
- 重启 Worker、重新登录 OA 等维护操作。

危险操作继续沿用现有确认门禁，不因界面简化而降低安全性。

## 7. 交互与视觉原则

- 主文案使用中文大白话；技术错误码仅在高级详情中出现。
- 绿色只表示该业务结果已经完成或链路健康，不能用于“仍在排队”。
- 黄色表示正在处理、曾使用兜底或无需立即处理。
- 红色只表示明确失败、未知飞书结果、需要人工操作或数据安全异常。
- 所有列表继续服务端分页，每页 50 项。
- 总览和已办资料每 5 秒静默刷新；用户输入搜索时不得丢失输入和当前页。
- 小屏幕保持三项导航可用；高级维护表格允许横向滚动。
- 状态不能只靠颜色表达，必须有中文标签。

## 8. 错误、安全和隐私

- 状态聚合失败时，卡片显示“状态暂不可用”，不得把缺失值当作 0 或完成。
- `next_run_at` 应从 systemd 定时器事实获取；获取失败时显示“等待系统调度信息”，不得伪造时间。
- Worker 心跳过期时显示“Worker 状态未知”，不能继续显示陈旧的“正在登录 OA”。
- OA 会话只在任务期间启动，任务结束后继续显示“OA 已退出”。
- 所有新测试使用合成或不可逆脱敏数据。
- OA 标识继续按文本处理；归档路径继续保存为相对 `data_root` 路径。
- 容器树最多遍历十层；达到上限必须归入“需要处理”。

## 9. 兼容与迁移

- 保留现有 API，避免旧页面或运维脚本失效。
- 新前端只把高级组件移动到折叠区，不删除其实现和操作入口。
- 不新增数据库迁移；所有简化状态由现有事实表聚合。
- 不修改现有定时器频率：待办/已办增量扫描继续每小时 05 分，夜间全量扫描继续每日 23:30。
- 不自动重试不可恢复格式，也不自动确认人工复核。

## 10. 验收标准

1. 新用户打开首页后，无需理解 Markdown、Curated 或任务队列，即可回答“已办做好没有”和“待办飞书是否正常”。
2. 默认一级导航只有“总览、已办资料、系统设置”。
3. 首页明确区分已同步、原件完整、MD 就绪和最终发布，不误报全部完成。
4. 待办卡显示真实频率、最近/下次扫描、飞书成功/失败、qwen 成功/兜底/失败。
5. 使用过确定性兜底时，页面显示“正常，但使用过兜底”，不显示“模型完全正常”。
6. 已办列表可按六种简化状态筛选，并保持服务端分页。
7. 复杂维护能力仍可从“系统设置 → 高级维护”访问。
8. 新接口和默认总览不包含 OA 正文、附件名、完整标题列表、凭据或绝对业务路径。
9. 后端相关 pytest、前端 TypeScript 检查和生产构建通过。
10. 实施过程不得改写、删除或上传任何 OA 数据，也不得发送飞书测试消息。
